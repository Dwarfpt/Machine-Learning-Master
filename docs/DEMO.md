# Сценарий демонстрации (защита, ~12 минут)

**Говорить честно:** рабочая модель после выбора переобучена на *всех* годах, поэтому игры из базы она уже «видела».
Честное качество — цифры теста 2013–2016, посчитанные **до** переобучения (стр. «Модели и XAI»). По-настоящему новые
игры на защите — это **форма «Новая игра»** и **файл новых игр 2017 года** через RPA (шаги 6–7).

## Перед защитой (за 15 минут)
1. Docker Desktop → в папке проекта `docker compose up -d` (MLflow: `docker compose --profile mlflow up -d mlflow`).
2. http://localhost:8000/health → `"model": "LightGBM (tuned)"`, `"llm_available": true`.
3. Вкладки: приложение :8501, n8n :5678, Gmail, Google-таблица, MLflow :5000, презентация.
4. Прогревочный запуск агента на любой игре (первая генерация медленнее).
5. Убедиться, что в `data/incoming/` пусто — файл для шага 7 положим при комиссии.

## 1. Дашборд (1 мин) — задача и данные
- **2 источника**: Kaggle (16 719 строк, VGChartz + Metacritic) + CORGIS (1 212) → 16 552 игры на 31 платформе
  (1980–2016), **8 140 с оценкой критиков**; 1 099 игр совпали в обоих источниках.
- 23 % игр получили оценку < 60; продажи таких игр ниже в разы (KPI сверху).
- Блок «Качество данных» — 23 находки по обоим источникам, у каждой решение.

## 2. Модели и XAI (2 мин) — почему модели можно доверять
- **3 этапа**: 11 моделей разных семейств → подбор гиперпараметров трёх лучших → комбинации пяти лучших
  (голосование «3 из 5», усреднение, стекинг). Победитель по PR-AUC на 5-fold CV — **LightGBM после подбора (0.574)**.
- **Голосование большинством проиграло (0.488)** — объяснить: теряется уверенность моделей.
- Тест 2013–2016: PR-AUC 0.29 против 0.14 у baseline (≈2×); рабочий порог находит **68 % провалов**.
- Accuracy обманчива: baseline «никогда не провал» = 86 %, лучшая модель = 80 %.
- Ниже на странице: **регрессия** (MAE ≈ 8.3 балла) и **AutoML PyCaret** (лидер Random Forest — подтверждает выбор).
- SHAP: главное — **история студии-разработчика**, тренд по годам, опыт студии, число платформ, сиквел, **возраст консоли**.

## 3. Хит → ничего не тратим (1 мин)
*Прогноз и действия → Игра из базы →* **Grand Theft Auto V** (PlayStation 3) → риск ≈ **1 %**, низкий, реальная оценка **97**.
Агент → только мониторинг, письма нет (строка в журнале есть).

## 4. Провал пойман → меры + человек в контуре (3 мин) — главный сценарий
*Игра из базы →* **Aliens: Colonial Marines** (X360, 2013) → риск ≈ **67 %**, высокий, реальная оценка **48**.
- SHAP-график, таблица мер (what-if через модель + стоимость/выгода).
- «Запустить AI-агента» (~30 с, LLM на GPU). Показать:
  - отчёт: причины, похожие игры, история издателя Sega, **строки «Из базы знаний (RAG)»**;
  - трассировку — **7 инструментов**, включая `search_knowledge_base`;
  - мера **QA (60 k$) → «ожидает согласования»** (порог 50 k$).
- Gmail: письмо **«Approval needed»** со ссылками Approve / Reject.

Запасные примеры пойманных провалов 2013–2014: **Knack** (PS4, 57 % / 54), **The Walking Dead: Survival Instinct**
(X360, 64 % / 32), **Dead Island: Riptide** (X360, 62 % / 57), **WWE 2K15** (PS3, 58 % / 55).

## 5. Решение менеджера (1.5 мин)
- В письме **Approve** → страница подтверждения API (или «Согласование (HITL)» в приложении).
- Письмо команде «Approved by manager», строки в Google-таблице, n8n → Executions — зелёный путь.
- Сказать: ссылки подписаны HMAC; решение попадает в базу знаний агента как прецедент.

## 6. Новая игра + what-if (1.5 мин) — главный трюк
*Новая игра:* «Movie Hero: The Game», PlayStation 4, 2017, Action, рейтинг T, издатель THQ, разработчик — пусто,
1 игрок, 4 ч, 1 платформа, не сиквел → риск ≈ **16 %, высокий**.
- Разработчик **Naughty Dog** → **6 %** (низкий). **FUN Labs** (средняя оценка их игр 49) → **24 %**.
- Вернуть пусто, отметить **сиквел** → **7 %**. Издатель **Nintendo** вместо THQ → **8 %**.
- Сказать: «главный фактор — репутация студии; это видно в SHAP и проверяется вживую».

## 7. RPA: автоматическое обновление данных (1.5 мин)
1. Скопировать `docs/examples/incoming_example.csv` в `data/incoming/` (9 вымышленных игр 2017 года, 2 строки с ошибками).
2. Запустить: страница **«Мониторинг» → «Обновить данные сейчас»** (или webhook n8n `nrg-refresh`; по расписанию — в 08:00).
3. Результат: **7 игр добавлено, 2 строки отбракованы** («unknown console», «year outside 1980–2035»), для 7 новых игр
   посчитан риск, **2 — высокий** (Movie Hero, Galaxy Racers) → письмо команде «2 upcoming game(s) at high risk»,
   строка `data_refresh` в Google-таблице, файл перенесён в `processed/`.
4. Повторный запуск с тем же файлом ничего не добавит — дубли пропускаются (это тоже можно показать).

## 8. Мониторинг и качество агента (1 мин)
- Журнал прогнозов, журнал обновлений данных, data drift (PSI, от 20 новых прогнозов).
- Оценка агента (`reports/agent_eval_*.json`): насколько LLM совпадает с модулем решений, срабатывания защит, время.

## Если что-то пошло не так
| Симптом | Что делать |
|---|---|
| «Rule-based агент (LLM недоступна)» | `docker compose restart llm`, 20 с; агент работает и без LLM (запасной режим) |
| Письма не пришли | n8n → Executions (красный узел = ошибка SMTP); Mailpit http://localhost:8025 |
| Строк нет в таблице | таблица открыта сервисному аккаунту на редактирование? |
| «Обновить данные» — 0 добавлено | файла нет в `data/incoming/` или эти игры уже загружены (дубли пропускаются) |
